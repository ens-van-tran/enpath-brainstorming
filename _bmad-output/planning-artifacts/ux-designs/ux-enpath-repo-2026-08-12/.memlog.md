- (decision) Prototype climax: En-Path successfully generates an assessment from the configured competency framework.
- (decision) Downstream desired outcome: aggregate assessment results and analyze skill gaps for an individual or a team without spreadsheet-based manual calculation.

- (change) Ownership conflict to reconcile: existing vault documentation assigns some team competency and matrix authoring to Managers, while the user's UX vision assigns competency authoring to HR Admin/L&D.
- (decision) HR Admin must be able to configure the calculation formula used by the competency framework and assessment.
- (decision) The prototype must visualize competency gaps at two aggregation levels: members within a selected team and comparison across teams.
- (decision) Within a team, HR Admin needs to identify members with the highest gaps and the specific skills driving those gaps.
- (decision) The experience must provide improvement suggestion text for a member's highest-gap skills.
- (decision) Assessment results must expose each team member's strengths and weaknesses to HR Admin.
- (change) The prototype value loop now includes analytics and guidance after assessment generation: framework and formula -> generated assessment -> results -> member and team gap visualizations -> strengths, weaknesses, and improvement suggestions.
- (decision) Gap uses a shortfall convention: Gap = Expected Score - Assessment Result.
- (decision) Competency comparison is visualized as an outlined target bar representing the expected score, with the assessment result filling the bar; the unfilled portion communicates the gap.
- (decision) Members are ranked by average competency gap when HR Admin identifies the highest-gap members in a team.
- (decision) Improvement guidance is not AI-generated in the prototype. HR Admin configures a reusable advice/message on each competency, and the system shows that message when the competency has a gap.
- (decision) Analytics must treat unassessed competency data as Unknown, never as a zero score or confirmed gap.
- (decision) Team and member analytics must show the comparison basis: team, role, level, framework version, assessment date, and assessment coverage.
- (assumption) A strength is a competency whose assessment result meets or exceeds its expected score; a weakness is a competency with a positive shortfall. This remains to be confirmed.
- (event) Confirmed-source extraction completed. It identified an unresolved ownership conflict between HR-led competency authoring and Manager-owned team matrix authoring in newer vault documents.
- (decision) Use a shared competency ownership model: HR Admin creates and maintains Global Competencies that apply across all teams.
- (decision) Each Manager creates and maintains Team Competencies scoped only to the Manager's team.
- (decision) Role-and-level competency matrices combine applicable Global Competencies with Team Competencies.
- (decision) HR Admin reviews submitted competency matrices and is the publication gate; HR Admin can publish or request changes.
- (change) Resolved the earlier ownership conflict by replacing HR-only authoring with shared HR/Manager authorship and HR publication governance.
- (decision) Use a constrained Formula Builder rather than arbitrary Excel-like formulas.
- (decision) Formula Builder configuration includes rating scale, competency criteria, criterion weights, competency weights, expected scores by role and level, mandatory competencies, and competency improvement messages.
- (decision) The system provides a live calculation preview and blocks submission or publication when weights, expected scores, or required formula inputs are invalid.
- (decision) Default calculation model: weighted criteria produce competency scores; weighted competency scores produce the overall assessment score; expected score minus actual score produces the gap.
- (decision) Assessment generation supports both team-wide and selected-member launch.
- (decision) HR Admin selects a team; all eligible members are selected by default, with controls to exclude or reselect individual members.
- (decision) Before generation, HR Admin previews the assessment form, selected participants, role/level matrix, and framework version that will be snapshotted.
- (decision) Generating an assessment materializes the currently published role-and-level matrix for each selected member.
- (decision) Each generated assessment collects two independent rating sources: Employee self-assessment and Manager assessment.
- (decision) HR Admin must be able to distinguish Employee and Manager scores rather than receiving an unexplained merged value.
- (assumption) The final score used for gap analytics remains unresolved until the user defines how Employee and Manager ratings are consolidated.
- (decision) The Actual Score used for gap analytics is a weighted combination of Employee self-assessment and Manager assessment.
- (decision) HR Admin configures the source weights in the Formula Builder; Employee and Manager source weights must total 100%.
- (decision) Analytics display Employee score, Manager score, weighted Actual Score, Expected Score, and Gap separately so the result remains explainable.
- (assumption) Prototype fixture may use Employee 30% and Manager 70% unless the user later specifies a different default.
- (decision) Company-level analytics rank teams by overall Average Gap.
- (decision) Detailed cross-team comparison is limited to Global Competencies shared by all teams.
- (decision) Team Competencies remain visible in within-team analytics but are not directly compared across teams with different competency sets.
- (decision) The analytics information architecture supports company overview -> selected team -> selected member -> competency and criterion detail.
- (decision) HR Admin configures Global Competency definitions, criteria, behavior anchors, advice messages, and company-wide assessment formula rules.
- (decision) Manager configures Team Competency definitions, criteria, behavior anchors, and advice messages for the Manager's team.

- (event) Opened a discovery question about whether assessments rate a competency directly by its shared behavior levels or calculate competency scores from weighted criteria.
- (decision) Support two competency assessment modes: Behavior/Level mode and Criteria/Point mode.
- (decision) Behavior/Level mode asks Employee and Manager to select a competency level using competency-specific behavior descriptions within the shared Level Model.
- (decision) Criteria/Point mode asks Employee and Manager to rate weighted criteria; the system calculates the competency score and resulting level.
- (decision) Each competency has one configured assessment mode at a time, and generated assessments render the corresponding input model.
- (assumption) The prototype will expose both assessment modes during competency authoring but use one primary mode for the full assessment-to-analytics demonstration.

- (decision) Technical Delivery demonstrates Criteria/Point mode.
